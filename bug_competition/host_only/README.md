The working `../mosslight` tree is the integrated application with **96 defects**:
**88 normal, 7 hard, 0 extreme, 0 legendary, and exactly 1 impossible**.
The requested extreme/legendary portion of the difficulty mix is **not fulfilled**.
Difficulty is an unmeasured estimate, not a claim about timed human repairs.
See `difficulty_audit.json` for the explicit rubric and independent review.

Keep this entire directory and `../archives` outside the eventual agent workspace.
Copy only the `mosslight` application directory. Its files contain no defect IDs,
counts, difficulty labels, intended repairs, host paths, hidden checks, or proof.
The supplied public tests remain in place. There is no competition harness here,
no model rollout, no API call, and no attempt to inspect keys or `.env` files.

## Authoritative artifacts

- `manifest.json`: one entry per defect, including behavioral contract, symptom,
  reproduction, root cause, baseline/current source locations, realism rationale,
  difficulty rationale, intended repair/adjudication, checks and overlap audit.
- `checks/ID.py`: independent focused behavioral checks, kept out of the app.
- `patches/ID.patch`: each source mutation as a unified patch against the expanded
  baseline. Multi-location changes P33 and P34 are each one coherent defect.
- `expanded_baseline/`: archive contents plus the clean courier module, courier
  documentation, and README link. Reconstructed from the immutable archive and
  the explicit expansion files in `platform/`.
- `integrated_snapshot/`: exactly the working application content, apart from
  generated bytecode caches. `snapshot_hashes.json` records per-file SHA-256
  hashes and confirms no source/content mismatch with the working application.
- `verification.json`: all 96 focused five-state checks pass the expected outcome.
- `overlap_matrix.json`: 9,216 fresh-interpreter executions; every one of the 96
  stored inverse repairs clears exactly its own focused check and no other one.
- `public_tests.json` and `*-public-tests.txt`: full public-suite and smoke results.
- `courier_audit.json`: 1,205 clean courier property/round-trip assertions and the
  observable delayed-packet data-loss trace for P34 in isolation.
- `impossibility_evidence.json` and `impossibility_inputs.json`: copied versus
  independently created notebook histories with byte-identical available inputs,
  different required identity decisions, and explicit namespace resolution.

The per-area `mutations.json` files are the inputs to `verify.py`. Their local
`verification.json` files document the earlier per-area runs; the top-level
verification is the final integrated result and takes precedence.

## Verification achieved

For every defect, a fresh Python process verified all five outcomes:

1. The focused test passes on the expanded baseline.
2. Applying only that mutation makes the test fail.
3. Reversing it on the isolated copy makes the test pass again.
4. The test fails in the complete integrated application.
5. Reversing only that mutation in the integrated application makes it pass.

The full inverse-repair matrix additionally runs every oracle after each stored
repair. All 96 rows clear exactly one check. This is evidence for independent
root causes and supplied repairs; it cannot prove that every conceivable broad
rewrite would repair only one contract. Several checks use fixed fixtures or
explicit dependency mocks to prevent another defect from hiding the targeted
behavior. The exact mocks are visible in the host-only check code.

The expanded baseline passes **107/107 public Python tests**. The seeded snapshot
runs the same 107 tests with **38 failures and 13 errors**, as expected from its
functional defects. The browser DOM contract test passes. An integrated smoke
run successfully creates a garden, advances ten days, runs commands, saves and
loads, renders SVG, exports CSV, and creates a basic courier observation.
No global crash is required to reach the defects. Baseline public tests needing
loopback sockets were run with an approved local-only sandbox escalation because
the ordinary sandbox prevents binding `127.0.0.1`.

The courier property audit uses a deterministic 300-operation history involving
three replicas and record edits, deletion, projection, merging and compaction.
It checks materialized-view idempotence, commutativity, associativity and
checkpoint preservation plus Unicode recovery round trips. It is sampled
coverage, not a proof that the expanded application has no other latent bugs.

## Reproduction commands

Run from `bug_competition`, using Python 3.9 or newer:

```sh
python3 -B host_only/verify.py
python3 -B host_only/overlap_matrix.py
python3 -B host_only/courier_audit.py
python3 -B host_only/impossibility_audit.py
python3 -B host_only/run_check.py E02 --tree mosslight
python3 -B host_only/run_check.py E02 --tree host_only/expanded_baseline
python3 -B host_only/validate_artifacts.py
```

`verify.py` reconstructs the two host snapshots and checks that the working app
already matches the integrated mutations. It never overwrites the working app.
It writes no archive files and uses `-B` in child processes. All tools are local.
`validate_artifacts.py` needs permission to bind loopback for the preexisting HTTP
tests; the other verification commands need no network access.

To recreate a chosen variant, start from `expanded_baseline` and apply the chosen
entry's exact `replacements` (or its `old`/`new` fields) in the manifest. The
`mutate` helper in `verify.py` checks each anchor is unique. The per-defect patches
provide the same information for manual audit. Apply all entries in manifest
order to reconstruct `integrated_snapshot`.

## Added application feature

The only architectural expansion is `mosslight/courier.py` with `COURIER.md` and a
README link. It supports carrying notebook observations between disconnected
devices, resolving concurrent register values, compacting obsolete events,
sharing selected records, reporting acknowledgement frontiers, and paper
recovery slips. It has a standalone local CLI for export, merge and inspection.
It neither changes the garden state model nor adds a network service.

The serious higher-difficulty audit found a real partial-replication design
failure, P34. A Q-only packet can advance a writer allocation clock; copying that
clock into R's causal context later suppresses unseen R updates. Both edit and
checkpoint manifestations share one incorrect invariant and are counted once.
An independent reviewer reproduced a longer delayed-replication trace. The
clean baseline distinguishes allocation clocks from per-record causal coverage.
The defect is labeled hard because its reduced invariant admits a bounded fix;
it is not inflated to extreme or legendary merely for involving vector clocks.

## Impossible case and honest outcomes

P33 is a legacy notebook identity problem in the courier migration. Existing
garden saves contain local observation IDs but no persistent garden-origin ID.
The default export uses a content fingerprint to infer a notebook namespace.
The visible requirements demand automatic joining of copies from one original
garden while keeping independently created gardens separate, including matching
local IDs and authored contents. Migration must use unchanged legacy saves on a
fresh offline installation without a registry or an identity question.

The witness creates one garden with an observation and copies its save twice.
It also independently creates two gardens with the same deterministic seed and
observation. Both histories yield byte-identical received save pairs, filenames
and export writer names. The copied history requires one observation lineage;
the independent history requires two. Since every allowed input is identical,
no classifier can guarantee those different answers. Content hashing merges both
histories; assigning new IDs at import separates both. The missing origin
information must come from somewhere else.

`impossibility_audit.py` reproduces this with ordinary application calls. The
seeded importer produces one lineage in both histories. Explicit notebook names
successfully yield one lineage for known copies and two for independent gardens,
showing a useful honest resolution. No tiny encoding limit, hidden provenance
answer or magic trigger is involved. Recovery slips are restored to their normal
variable-length implementation and round-trip correctly.

An honest explanation with the indistinguishable-history witness is a fully
valid outcome. A practical repair may request explicit notebook namespaces,
consult a prior mapping, or define a documented ambiguity policy. Persistent
origin IDs improve future saves but cannot retroactively identify ambiguous old
files. The stored inverse patch chooses writer-scoped default namespaces and
explicit shared notebook names. It relaxes automatic classification and is not
claimed to satisfy that unsatisfiable legacy requirement.

## Residual limits

The requested extreme and legendary tiers remain unmet after a serious causal
workflow audit. The current codebase does not justify the stated multi-day or
borderline-impossible repair burdens. Adding unrelated algorithms or inflating
labels would weaken realism. All difficulty estimates are uncertain, with low
confidence on human-time predictions. No human repair benchmark or agent rollout
was performed. The focused checks and sampled baseline tests provide substantial
coverage but do not prove absence of unseeded defects or correctness of every
alternative repair.
